1Multiple Accounts & WhatsApp Numbersالحسابات المتعددة وأرقام واتساب

✅ Multiple accounts (businesses) — Yes, fully✅ حسابات متعددة (أنشطة) — نعم، بالكامل

The platform is multi-tenant. Every record — contacts, conversations, templates, chatbots, orders, team, settings — is scoped to its owning account and completely isolated; one account can never see another's data. A super-admin switches between accounts with the client switcher in the top nav, and each account has its own team, WhatsApp number, Facebook Page, and Instagram.المنصّة متعدّدة المستأجرين. كل سجلّ — جهات الاتصال، والمحادثات، والقوالب، والبوتات، والطلبات، والفريق، والإعدادات — مرتبط بحسابه المالك ومعزول تمامًا؛ فلا يرى حساب بيانات حساب آخر أبدًا. يتنقّل المشرف العام بين الحسابات عبر مبدّل الحسابات في الشريط العلوي، ولكل حساب فريقه ورقم واتساب وصفحة فيسبوك وإنستغرام الخاصة به.

✅ Multiple WhatsApp numbers — Yes: one number per account✅ أرقام واتساب متعددة — نعم: رقم واحد لكل حساب

Each account connects exactly one WhatsApp number. Because you can create many accounts, the system runs many numbers side by side, and inbound messages route to the correct account automatically by their phone-number ID.يربط كل حساب رقم واتساب واحدًا فقط. وبما أنك تستطيع إنشاء حسابات كثيرة، يُشغّل النظام أرقامًا كثيرة جنبًا إلى جنب، وتُوجَّه الرسائل الواردة إلى الحساب الصحيح تلقائيًا عبر معرّف رقم الهاتف.

2Recommended Hosting Setupإعداد الاستضافة الموصى به

The one constraint that shapes everything: Meta must reach your webhook over public HTTPS. Even though your devices are on the LAN, WhatsApp/Instagram/Messenger deliver inbound messages by calling https://your-domain/api/webhooks/* from the internet. So the design is “publicly-reachable webhook + your team uses the UI over HTTPS.”القيد الذي يحكم كل شيء: يجب أن تصل ميتا إلى الويب هوك عبر HTTPS عام. فحتى لو كانت أجهزتك على الشبكة المحلية، يُسلّم واتساب/إنستغرام/ماسنجر الرسائل الواردة باستدعاء https://your-domain/api/webhooks/* من الإنترنت. فالتصميم هو «ويب هوك متاح للعموم + فريقك يستخدم الواجهة عبر HTTPS».

Meta (WhatsApp / IG / Messenger) ──HTTPS──▶ ┌────────────────────────────────┐ Your team & LAN devices ──HTTPS──▶ │ Cloudflare Tunnel (edge TLS) │ │ │ │ │ Caddy (proxy, :80) │ │ │ │ │ app:3000 worker │ │ Postgres Redis │ └────────────────────────────────┘ one docker compose stack
  • Server: an always-on Linux box (Ubuntu) with Docker + Compose. For one hotel, 2–4 vCPU / 8 GB RAM / SSD is plenty. On-prem or a small cloud VPS both work.الخادم: جهاز لينكس دائم التشغيل (أوبونتو) مع Docker + Compose. لفندق واحد، 2–4 نوى / 8 جيجابايت رام / SSD تكفي بوفرة. سواء محليًا أو على خادم سحابي صغير.
  • Cloudflare Tunnel gives public HTTPS with no port-forwarding and no exposed LAN — the tunnel dials out; Meta and your team reach the app via a hostname like hub.opalhotel.com.نفق Cloudflare يوفّر HTTPS عامًا بلا إعادة توجيه منافذ وبلا كشف الشبكة المحلية — يتّصل النفق للخارج؛ وتصل ميتا وفريقك للتطبيق عبر اسم مضيف مثل hub.opalhotel.com.
  • Caddy is the internal reverse proxy (compression + security headers). Public TLS is handled at Cloudflare's edge, so Caddy runs plain HTTP inside.Caddy هو الوكيل العكسي الداخلي (ضغط + ترويسات أمان). ويُدار TLS العام على حافة Cloudflare، فيعمل Caddy بـ HTTP بسيط داخليًا.
  • LAN devices just open https://hub.opalhotel.com in any browser — nothing to install, protected by the app's own login.أجهزة الشبكة تفتح https://hub.opalhotel.com في أي متصفّح — لا شيء يُثبَّت، ومحميّة بتسجيل دخول التطبيق نفسه.
💡 Tip — keep LAN traffic local:💡 نصيحة — أبقِ حركة الشبكة محلية: add split-horizon DNS so inside devices resolve hub.opalhotel.com to the server's LAN IP. Uncomment ports: ["80:80"] on caddy to reach it directly.أضِف DNS بأفق منقسم لتترجم الأجهزة الداخلية hub.opalhotel.com إلى عنوان الخادم المحلي. وأزِل التعليق عن ports: ["80:80"] في caddy للوصول المباشر.

3Deploy in 5 Stepsالنشر في 5 خطوات

  1. Clone the repo: git clone <your-repo> opal-hub && cd opal-hubاستنسخ المستودع: git clone <your-repo> opal-hub && cd opal-hub
  2. Add the three files below at the repo root (also in deploy/).أضِف الملفات الثلاثة أدناه في جذر المستودع (وهي أيضًا في deploy/).
  3. Create a Cloudflare Tunnel, map hub.opalhotel.com → http://caddy:80, and paste the token into .env.أنشئ نفق Cloudflare، واربط hub.opalhotel.com ← http://caddy:80، وألصق الرمز في .env.
  4. Fill every secret in .env. Hash the admin password: node scripts/hash-password.mjs 'pw'.املأ كل سرّ في .env. وجزّئ كلمة مرور المسؤول: node scripts/hash-password.mjs 'pw'.
  5. Launch: docker compose -f docker-compose.prod.yml up -d --build — migrations + admin seed run automatically.شغّل: docker compose -f docker-compose.prod.yml up -d --build — تُطبَّق الترحيلات وبذرة المسؤول تلقائيًا.
✅ Then:✅ بعدها: point each Meta webhook to https://hub.opalhotel.com/api/webhooks/whatsapp (and /instagram, /messenger) and whitelist the domain in your Meta app.وجّه كل ويب هوك من ميتا إلى https://hub.opalhotel.com/api/webhooks/whatsapp (و/instagram و/messenger) وأضِف النطاق للقائمة المسموحة في تطبيق ميتا.

docker-compose.prod.yml

docker-compose.prod.yml
name: opal-hub

x-app: &app
  build: .
  image: opal-hub:latest
  env_file: .env
  restart: unless-stopped

services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes: ["pgdata:/var/lib/postgresql/data"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    command: ["redis-server", "--appendonly", "yes"]
    volumes: ["redisdata:/data"]

  migrate:
    <<: *app
    restart: "no"
    command: ["sh", "-c", "npx prisma migrate deploy && npm run seed:admin"]
    depends_on:
      postgres: { condition: service_healthy }

  app:
    <<: *app
    environment:
      NODE_ENV: production
      PORT: "3000"
    expose: ["3000"]
    command: ["npm", "run", "start"]
    depends_on:
      postgres: { condition: service_healthy }
      redis: { condition: service_started }
      migrate: { condition: service_completed_successfully }

  worker:
    <<: *app
    environment:
      NODE_ENV: production
    command: ["npm", "run", "worker"]
    depends_on:
      postgres: { condition: service_healthy }
      redis: { condition: service_started }
      migrate: { condition: service_completed_successfully }

  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    depends_on: [app]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    # ports: ["80:80"]   # uncomment for direct LAN access (http://SERVER-IP)

  cloudflared:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: ["tunnel", "run", "--token", "${CLOUDFLARE_TUNNEL_TOKEN}"]
    depends_on: [caddy]

volumes:
  pgdata: {}
  redisdata: {}
  caddy_data: {}
  caddy_config: {}

Caddyfile

Caddyfile
# Cloudflare terminates public TLS at the edge and forwards to Caddy on :80.
# Caddy adds compression + security headers, then proxies to the Next.js app.
:80 {
	encode zstd gzip
	header {
		-Server
		Referrer-Policy "strict-origin-when-cross-origin"
		X-Content-Type-Options "nosniff"
		X-Frame-Options "SAMEORIGIN"
	}
	reverse_proxy app:3000
}

4Access, Security & Backupsالوصول والأمان والنسخ الاحتياطي

  • Firewall: with Cloudflare Tunnel you can close all inbound ports — only allow 22 (SSH).الجدار الناري: مع نفق Cloudflare يمكنك إغلاق كل المنافذ الواردة — واسمح فقط بالمنفذ 22 (SSH).
  • Security: the app's own login is the primary gate. For extra protection add Cloudflare Access in front of the UI — but leave /api/webhooks/* and the OAuth callback open.الأمان: تسجيل دخول التطبيق هو الحاجز الأساسي. ولمزيد من الحماية أضِف Cloudflare Access أمام الواجهة — مع إبقاء /api/webhooks/* ومسار OAuth مفتوحين.
  • Backups: the pgdata volume holds everything. Nightly dump: docker compose exec postgres pg_dump -U opal opalhub | gzip > backup.sql.gz — send it off-box.النسخ الاحتياطي: حجم pgdata يحوي كل شيء. نسخة ليلية: docker compose exec postgres pg_dump -U opal opalhub | gzip > backup.sql.gz — واحفظها خارج الخادم.
  • Updates: git pull && docker compose -f docker-compose.prod.yml up -d --build — migrations re-run automatically.التحديثات: git pull && docker compose -f docker-compose.prod.yml up -d --build — تُعاد الترحيلات تلقائيًا.
  • Scale: add worker replicas as volume grows — keep WA_MPS × workers ≤ your Meta tier.التوسّع: أضِف نسخ عامل مع نموّ الحجم — مع إبقاء WA_MPS × workers ≤ فئتك في ميتا.
⚠️ Don't⚠️ لا make the whole app LAN-only — Meta's webhook and the OAuth callback must stay publicly reachable over HTTPS.تجعل التطبيق كلّه محليًا فقط — فويب هوك ميتا ومسار OAuth يجب أن يبقيا متاحين للعموم عبر HTTPS.
