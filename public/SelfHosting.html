1Multiple Accounts & WhatsApp Numbers

✅ Multiple accounts (businesses) — Yes, fully

The platform is multi-tenant. Every record — contacts, conversations, templates, chatbots, orders, team, settings — is scoped to its owning account and completely isolated; one account can never see another's data. A super-admin switches between accounts with the client switcher in the top nav, and each account has its own team, WhatsApp number, Facebook Page, and Instagram.

✅ Multiple WhatsApp numbers — Yes: one number per account

Each account connects exactly one WhatsApp number. Because you can create many accounts, the system as a whole runs many numbers side by side, and inbound messages route to the correct account automatically by their phone-number ID.

⚠️ The one limit: the system does not currently support multiple WhatsApp numbers inside a single account (two numbers sharing one inbox). That specific setup would be a small schema change (making an account's WhatsApp connection one-to-many).

2Recommended Hosting Setup

The one constraint that shapes everything: Meta must reach your webhook over public HTTPS. Even though your devices are on the LAN, WhatsApp/Instagram/Messenger deliver inbound messages by calling https://your-domain/api/webhooks/* from the internet. So the design is “publicly-reachable webhook + your team uses the UI over HTTPS.”

Meta (WhatsApp / IG / Messenger) ──HTTPS──▶ ┌────────────────────────────────┐ Your team & LAN devices ──HTTPS──▶ │ Cloudflare Tunnel (edge TLS) │ │ │ │ │ Caddy (proxy, :80) │ │ │ │ │ app:3000 worker │ │ Postgres Redis │ └────────────────────────────────┘ one docker compose stack
  • Server: an always-on Linux box (Ubuntu) with Docker + Compose. For one hotel, 2–4 vCPU / 8 GB RAM / SSD is plenty. On-prem or a small cloud VPS both work.
  • Cloudflare Tunnel gives public HTTPS with no port-forwarding and no exposed LAN — the tunnel dials out; Meta and your team reach the app via a hostname like hub.opalhotel.com.
  • Caddy is the internal reverse proxy (compression + security headers). Public TLS is handled at Cloudflare's edge, so Caddy runs plain HTTP inside.
  • LAN devices just open https://hub.opalhotel.com in any browser — nothing to install, protected by the app's own login.
💡 Tip — keep LAN traffic local: add split-horizon DNS (via your router or Pi-hole) so inside devices resolve hub.opalhotel.com to the server's LAN IP. Uncomment ports: ["80:80"] on the caddy service to reach it directly.

3Deploy in 5 Steps

  1. Clone the repo onto the server: git clone <your-repo> opal-hub && cd opal-hub
  2. Add the three files below at the repo root: docker-compose.prod.yml, Caddyfile, and .env (they're also in the deploy/ folder).
  3. Create a Cloudflare Tunnel (Zero Trust → Networks → Tunnels), map hub.opalhotel.com → http://caddy:80, and paste the token into .env.
  4. Fill every secret in .env (see the template). Generate the admin password hash with node scripts/hash-password.mjs 'your-password'.
  5. Launch: docker compose -f docker-compose.prod.yml up -d --build — migrations + admin seed run automatically, then web + worker start.
✅ Then: point each Meta webhook to https://hub.opalhotel.com/api/webhooks/whatsapp (and /instagram, /messenger) and whitelist the domain in your Meta app.

docker-compose.prod.yml

docker-compose.prod.yml
name: opal-hub

x-app: &app
  build: .
  image: opal-hub:latest
  env_file: .env
  restart: unless-stopped

services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes: ["pgdata:/var/lib/postgresql/data"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    command: ["redis-server", "--appendonly", "yes"]
    volumes: ["redisdata:/data"]

  migrate:
    <<: *app
    restart: "no"
    command: ["sh", "-c", "npx prisma migrate deploy && npm run seed:admin"]
    depends_on:
      postgres: { condition: service_healthy }

  app:
    <<: *app
    environment:
      NODE_ENV: production
      PORT: "3000"
    expose: ["3000"]
    command: ["npm", "run", "start"]
    depends_on:
      postgres: { condition: service_healthy }
      redis: { condition: service_started }
      migrate: { condition: service_completed_successfully }

  worker:
    <<: *app
    environment:
      NODE_ENV: production
    command: ["npm", "run", "worker"]
    depends_on:
      postgres: { condition: service_healthy }
      redis: { condition: service_started }
      migrate: { condition: service_completed_successfully }

  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    depends_on: [app]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    # ports: ["80:80"]   # uncomment for direct LAN access (http://SERVER-IP)

  cloudflared:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: ["tunnel", "run", "--token", "${CLOUDFLARE_TUNNEL_TOKEN}"]
    depends_on: [caddy]

volumes:
  pgdata: {}
  redisdata: {}
  caddy_data: {}
  caddy_config: {}

Caddyfile

Caddyfile
# Cloudflare terminates public TLS at the edge and forwards to Caddy on :80.
# Caddy adds compression + security headers, then proxies to the Next.js app.
:80 {
	encode zstd gzip
	header {
		-Server
		Referrer-Policy "strict-origin-when-cross-origin"
		X-Content-Type-Options "nosniff"
		X-Frame-Options "SAMEORIGIN"
	}
	reverse_proxy app:3000
}

4Access, Security & Backups

  • Firewall: with Cloudflare Tunnel you can close all inbound ports — only allow 22 (SSH). Nothing else needs to be open.
  • Security: the app's own login is the primary gate. For extra protection you can add Cloudflare Access (email/SSO) in front of the UI — but leave /api/webhooks/* and the OAuth callback open so Meta can reach them.
  • Backups: the pgdata volume holds everything. Nightly dump: docker compose exec postgres pg_dump -U opal opalhub | gzip > backup-$(date +%F).sql.gz — send it off-box.
  • Updates: git pull && docker compose -f docker-compose.prod.yml up -d --build — migrations re-run automatically.
  • Scale: add worker replicas if broadcast volume grows — keep WA_MPS × workers ≤ your Meta messaging tier.
⚠️ Don't make the whole app LAN-only — Meta's webhook and the OAuth callback must stay publicly reachable over HTTPS. Keep the app behind HTTPS + login; optionally restrict the UI with Cloudflare Access.
